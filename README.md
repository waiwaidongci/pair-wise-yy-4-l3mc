# 水下考古工作台

直接打开 `index.html` 使用（无需构建，`file://` 下也可运行，数据存浏览器 localStorage）。

页面分两个视图，顶部切换：

## 沉船标记图（原功能）

点击沉船平面图添加标记，按类型筛选、编辑/删除、潜次时间线、导出标记 JSON，均保持原有行为，数据键 `zfl30Marks`。

## 脱盐监护台

按**槽位**管理出水遗物脱盐，三栏：

- **待换水**：在槽且无异常的批次。每件登记槽号、材质、入槽时刻、最近电导率与换水记录，并列出仍需留在待换水的原因。
- **异常**：同槽混放材质冲突、电导率回升（盐分反弹）、超过超期上限仍未换水。
- **结批**：已结批存档批次；复核员确认排水量、余盐后才允许结批（缺项或不达标时拒绝）。

### 判定规则（可在工具栏调整）

1. 最近电导率未降到阈值（默认 100 μS/cm）→ 留在待换水；
2. 距入槽或最近一次换水不足最小间隔（默认 24h）→ 留在待换水；
3. 同槽材质分组不同（陶瓷/木质/金属/未知混放）→ 材质冲突异常，禁止结批；
4. 最近电导率高于上一次读数 → 回升异常；超过超期上限（默认 72h）未换水 → 超期异常。

整槽全部达标且无异常才出现“复核结批”，由复核员填入**排水量**与**余盐**后结批。

### 历史读数更正

在“结批”栏打开已结批批次，对任一历史读数更正并填写原因、更正人：原批次标记 **已作废** 并原样留档（含旧读数与判定参数），整槽遗物回槽、按新数据重新判定，可在待换水/异常栏看到新结果。当前批次读数也可直接更正，立即重判。

### 筛选与导出

材质、关键字（槽号/编号）、状态筛选均跟随当前在槽批次；“导出当前批次JSON”按当前筛选结果导出（含每槽判定状态与异常），结批详情内可单独导出该批次 JSON。

## 文件结构

- `index.html` —— 两个视图的页面与样式
- `js/desalination.js` —— 脱盐判定（纯规则：阈值、间隔、材质冲突、回升/超期异常）
- `js/batches.js` —— 批次存档与历史重判（localStorage、结批、作废留档、导出载荷）
- `js/app.js` —— 页面操作（视图切换、标记地图/编辑/时间线、监护台渲染、筛选、JSON 导出）

数据键：`zfl30Marks`（标记）、`zfl30DesalState`（脱盐在槽遗物与批次存档）、`zfl30LastReviewer`（上次复核员）。首次打开会写入演示数据（T-01 待换水、T-02 材质冲突异常、T-03 可结批、T-04 已结批示例）。
